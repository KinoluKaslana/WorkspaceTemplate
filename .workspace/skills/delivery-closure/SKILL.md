# Delivery Closure — 交付闭环 skill

把 `AGENT_RULES.md` §9 的完成标准落成**无歧义的机械步骤**。触发本 skill 的任务，在六步全部完成前**不得声明完成**；任一步无法完成只能作为「限制/未决项」向用户披露并获得接受。Agent 只按流程执行，不做自由发挥。

## 触发条件

- 任务模式（`AGENT_RULES.md` §1）产生了持久化产物（新建/修改文件、部署、发布、工具登记），Agent 准备收尾或声明完成；
- 用户要求「收尾 / 交付闭环 / 检查交付」。

不触发：纯问答/只读任务；无持久化产出的对话。用户明确豁免时记录理由后跳过（§9 同款豁免语义，边界不放松）。

## 前置事实（先读，不可跳过）

1. **政策与流程的分工**：`AGENT_RULES.md` §9 定义「什么是完成」（政策），本 skill 定义「怎么一步步做到」（程序）；§9 完成标准的指针条款即指向本 skill。
2. **note 纪律**：新建 note 前必须先查 `notes/INDEX.md`（§9 记忆卫生——合并优先，不平行新增碎片）。
3. **部署事实源**：本工作区的「部署/发布方式」只认 `WORKSPACE.md`（交付与验收节）与 `TOOLS.md` 的登记；没有登记的部署动作不发明，先向用户确认。
4. **Python 运行时**：跑 `notes/rebuild_index.py` 必须用 `.workspace/bootstrap.json` 登记的解释器/venv（下文记作 `<py>`），不裸调系统 `python`。

## 标准流程（六步，顺序固定）

### 第 1 步：产物清点

```bash
# 在 Workspace 根执行
git status --short                            # 有仓时：列出全部改动
ls -la <task-slug>-<yy-mm-dd>/ 2>/dev/null    # 任务目录产物
```

逐个产物确认三件事：**存在、非空、路径在授权范围内**（§3）。清单原样写进第 6 步报告。

### 第 2 步：查 INDEX（note 判定的输入）

```bash
cat notes/INDEX.md
# 路由未命中或需要扩展检索时：
grep -i -C2 '<关键词>' notes/_INVERTED.md
```

判断本次任务是否形成「可跨任务复用的正/负经验 / 重要业务结论 / 规则-环境-工具变更」（§9 建 note 门槛）。

### 第 3 步：note 三选一（决定必须写进报告）

| 判定 | 动作 |
|---|---|
| 与既有 note 实质重合 | **合并**更新既有 note；旧结论被取代时在旧 note frontmatter 写 `superseded_by: <新name>` |
| 新的可复用经验 | 从 `notes/_TEMPLATE.md` **新建** `notes/<task-slug>-<yy-mm-dd>.md`，补齐双向 `related` |
| 无可复用经验 | **豁免**——理由必须非空并写进最终报告（纯机械改动 / 用户豁免 / 无新结论） |

### 第 4 步：索引回写

```bash
<py> notes/rebuild_index.py
```

exit 0 且无 `[WARN]` 才算通过；有 warning 说明 note 图结构损坏（双向 related 断链、必填字段缺失等），修复后重跑。

### 第 5 步：外部动作与机械验证（若适用）

有对外产物时按登记方式执行，**每项都要机械验证**——命令输出是唯一证据，口头「应该没问题」无效：

| 产物类型 | 动作与验证示例（以 WORKSPACE/TOOLS 登记为准） |
|---|---|
| 已上线站点/书稿 | 部署脚本 → `curl -sS -o /dev/null -w '%{http_code}' <URL>` 应为 200，内容抽查含预期标题 |
| 代码改动 | 测试/lint 通过（exit 0）；按授权提交后 `git log -1 --stat` 核对 |
| 发布/版本 | tag/release 存在性验证 |

无外部动作时在报告注明「第 5 步不适用」。验证必须**在本流程内执行**，引用任务早期的旧输出不算数（产物可能已变）。

### 第 6 步：完成声明（报告格式固定）

按以下顺序输出，**缺项即未完成**：

1. **产物**：第 1 步清单（路径 + 验证状态）；
2. **note 决定**：合并（哪篇）/ 新建（name）/ 豁免（理由）；
3. **索引**：`rebuild_index.py` 退出码与 warning 数；
4. **外部动作与验证**：命令 + 观测值（200 / exit 0 / …），或「不适用」；
5. **限制/未决项**：未完成的步骤 + 原因；
6. 仅当 1–4 全绿时，才可写「任务完成」。

## 陷阱

- **别把「构建成功」当「交付完成」**——部署与线上验证是另外两步（真实翻车案例：书稿构建通过即收尾，note 检查与部署全靠用户提醒补齐）。
- **豁免理由不许空着**，也不许写「略」「同上」。
- 第 5 步验证必须是新执行的命令输出；引用早先结果 = 未验证。
- MCP Python 模式跑不了本地脚本时：按 §9 由 Agent 文件工具按同格式手工维护索引，并在报告注明「未运行 rebuild_index」的限制。
- 本 skill 不扩大授权：部署、发布、提交仍受 §7 与用户范围约束；hook 化的机械守卫（若工作区已配置）只是兜底，不是绕过本流程的理由。
